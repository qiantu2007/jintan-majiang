# 联机服务部署（免费，国内直连可用）

## 为什么要分两个文件夹

原来只有 `_服务端` 一个 Worker，部署后拿到的地址是 `xxx.workers.dev`。
**这个后缀在国内被拦了两道**（实测）：

| 拦截层 | 现象 |
|---|---|
| DNS | 查 `jintan-mahjong.qiantu2007.workers.dev` 返回 `31.13.80.37` / `157.240.17.36` —— 都是 Facebook 的地址段，连过去永远没人应答 |
| TLS | 就算手工把 IP 指对，握手时按域名（SNI）会被直接掐断连接 |

而 `pages.dev` 这个后缀两层都干净：

| 测试 | 结果 |
|---|---|
| `pages.dev` 域名解析 | `104.18.20.135`，真的 Cloudflare IP |
| 直连 Cloudflare 网段（不挂代理） | 通，120~280 毫秒 |
| SNI = `anything.pages.dev` 裸握手 | 成功，194 毫秒 |
| SNI = `jintan.workers.dev` 裸握手 | 连接被强制关闭 |

同一批机器、同一个账号，只是换个门牌号就能进。所以：

- `_服务端`（Worker）—— 放房间逻辑（`Room` 这个 Durable Object 类）。
  它的 workers.dev 地址进不去**没关系，用不到**。
- `_服务端Pages`（Pages）—— 对外的门，给出能用的 `pages.dev` 网址，
  收到请求后在 Cloudflare 内部转给上面那个 Worker。

之所以不能合成一个：**Pages 不允许自己定义 Durable Object**，只能绑定 Worker 里的。
这是 Cloudflare 的硬性限制，不是绕路。

## 部署（两条命令）

第一次要先登录（以前登过就跳过）：

```bash
npx wrangler login
```

**第一步，房间逻辑。** 在 `_服务端` 文件夹里：

```bash
npx wrangler deploy
```

打印出来的 workers.dev 网址忽略掉，用不到。

**第二步，对外入口。** 在 `_服务端Pages` 文件夹里：

```bash
npx wrangler pages deploy --branch production
```

打印出来的 `https://xxx.pages.dev` **才是要填进游戏的地址**。

> **`--branch production` 不能省。** 这个 Pages 项目的生产分支叫
> `production`，本仓库的分支叫 `main`。不写这个参数，wrangler 会照当前
> git 分支名把东西发到**预览环境**，命令照样打印「部署成功」，
> 但 `jintan-mj.pages.dev` 纹丝不动。
>
> 2026-09-02 踩过一次：以为服务端更新了，其实生产环境还是旧的。
> 是靠 `/health` 回的版本号才发现的 —— 拿浏览器打开
> <https://jintan-mj.pages.dev/health>，看到的版本号得和
> `src/app.js` 里的 `VERSION` 一致才算真的上去了。
>
> 这个坑是仓库开始用 git 之后才出现的：以前没有 git 上下文，
> wrangler 默认发生产，所以老命令一直好使。

## 检查绑定有没有配上

`wrangler.toml` 里已经写好了 ROOM 绑定。如果部署后开房间报
「ROOM 绑定没配置」，去后台手动加一次：

1. dash.cloudflare.com → Workers & Pages → 点开 `jintan-mj` 这个 Pages 项目
2. Settings → Bindings → Add → Durable Object
3. Variable name 填 `ROOM`，namespace 选 `jintan-mahjong` 里的 `Room`
4. 重新部署一次

## 验证

浏览器打开 `https://你的地址.pages.dev/health`，看到 `ok` 就是通的。

或者直接在游戏里「和朋友一起打 → 检查网络」，打勾就行。
